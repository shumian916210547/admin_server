# 通用功能与界面修复记录

验证日期：2026-11-10。范围为 Express 通用数据服务、浏览器 API/Parse 兼容层、动态路由及通用列表/表单/详情/CSV；复用现有令牌和权限契约。

## 已修复的问题

| 问题 | 修复结果 | 验证方式 |
| --- | --- | --- |
| 后端把普通类名字符串作为构造函数调用，通用新增失败 | 普通记录使用 `new Parse.Object(className)`；用户仍使用 `Parse.User` 和 signUp | 真实 Parse SDK、内存写入适配器 |
| 复制含 null 的记录报错 | 保留空值、日期、循环引用；移除函数字符串 eval | 前端离线断言、空备注真实界面编辑 |
| Date 变成空对象；未修改的日期字符串无法按类型保存 | Parse 适配层编码 `Date`，Schema 服务规范化日期字符串，BFF 解码成 Date；详情与 CSV 共用格式化 | 前后端离线断言 |
| 日期区间查询缺少契约 | 只为真实 Date 字段接受包含上下界的白名单运算符；继续与服务端授权范围取交集 | 真实 Parse Query 编码、非法字段/日期/运算符拒绝断言 |
| 清空 Pointer 时提交空字符串 | 统一序列化为 null；编辑只保存本次表单字段 | 前端离线断言 |
| 全量选项/CSV 请求被 BFF 500 条上限截断 | 每页 500 顺序读取，以 createdAt/objectId 稳定排序；超出分页范围明确报错 | 1203 条内存记录验证无缺失/重复 |
| 筛选保留旧页码、重置保留旧对象、删除末页后空白 | 查询从第一页开始；筛选直接读取当前父级对象；刷新时校正页码 | Chromium 真实交互 |
| 旧请求覆盖新结果、查询失败被当成空列表 | 请求序号保护最新结果；失败保留原数据和错误提示；记录/总数一次请求返回 | 主动制造慢/快响应及 500 错误 |
| 保存可重复点击或中途关闭；再次新增残留默认值 | 校验和保存期间禁用操作，提交失败保留输入，每次打开按 Schema 重建独立默认值 | 必填校验、慢保存、失败重试、重新打开 |
| 导出关闭后沿用旧勾选 | 每次打开清理勾选；过期请求不提交结果；加载期间禁用确认 | 两次导出及真实 CSV 下载 |
| 恢复会话成功后业务 403/500 仍导致退出 | 只在恢复失败或重试仍为 401 时广播会话失效 | 真实 Axios 自定义适配器 |
| 403 被提示为会话失效，通知持续时间被写成几毫秒 | 单独提示权限不足；使用毫秒单位可读通知 | 离线检查与浏览器异常流程 |
| CSV 的零被抹除，空数组报错，空日期显示当前时间 | 列表/详情/CSV 共用 Schema 格式化器，正确保留 0、false、空值和 Parse Date | 离线断言、真实 CSV 下载 |
| 动态组件探测同步引入全部页面 | 通过异步上下文键名查找组件，仍支持 views、components、目录 index 和 404 回退 | 构建、动态深链接、真实浏览器路由装配 |
| 路由编辑旧字段残留，删除前先改动本地数组 | 所有字段按当前记录回填；删除使用新数组并刷新服务端状态 | 代码审查、前端构建（未对真实配置执行删除） |
| 退出仅删除 Cookie，旧 Cookie 仍可重放 | 按可信企业/用户/jti 撤销当前会话，保留撤销标记，其他设备不受影响 | 临时 PostgreSQL 上真实登录、退出、旧 Cookie 重放拒绝及另一会话仍有效 |
| 会话恢复接口 503 导致误退出 | 网络/恢复服务临时故障保留本地状态，仅明确 401 才清理 | Axios 离线故障断言 |
| Parse 推送链路残留 UUID 中危依赖 | 保持 CommonJS v4 接口，统一使用已修复 UUID 11.1.1；前后端生产审计均为 0 | 实际父依赖解析检查、模块加载与生产依赖审计 |

## 界面统一

- 自动生成的数据页面采用已有管理页标题层级；新增、详情与导出使用 Schema 中文别名。
- 表格、筛选栏、弹窗、通知共用 `tokens.scss` 的色彩、间距、圆角与层级。布尔筛选支持“是/否/不筛选”。
- 多行编辑从绝对定位改为网格布局，避免长内容、多个多行字段和全屏状态重叠；窄屏标签换行，日期控件填满可用宽度。
- 手机筛选区独立滚动，为数据和分页保留空间；详情在窄屏使用单列；弹窗底部按钮可换行。
- 覆盖 1440px 桌面、390px 手机、600px 短屏、真实深色偏好以及横向/纵向布局。截图全部使用内存演示数据，未写入源码仓库。

## 可复现验证

```powershell
cd vue_admin
npm run test:regression
npm run security:check
npm run build
npm run audit:prod
# 保持静态服务器运行，另开终端执行后端命令
node dist/app.js

cd ../admin_server
npm run test:regression
npm run test:admin-ui
npm run check
npm run security:check
npm run audit:prod
# PostgreSQL 工具目录不在 PATH 时指定；例如本机安装目录中的 bin
$env:ADMIN_TEST_PG_BIN="<PostgreSQL bin 目录>"
$env:ADMIN_TEST_FULL_DOMAIN="1"
npm run test:integration
```

浏览器脚本默认访问 `http://localhost:4200`，可用 `ADMIN_UI_TEST_URL` 修改。Windows 默认使用已安装的 Edge，其余平台默认使用 Playwright Chromium；可用 `ADMIN_UI_BROWSER_CHANNEL` 指定已安装通道。全部 API 在页面中拦截，不需要初始化管理员、BFF 或 PostgreSQL。`ADMIN_UI_SCREENSHOT_DIR` 可指定源码仓库以外的脱敏截图目录。浏览器关闭后不保留会话。

前后端离线回归、隔离浏览器交互、构建、语法和安全门禁通过。真实集成脚本创建随机临时 PostgreSQL 集群，执行首次初始化、协同/视频迁移、Cookie 登录、CSRF、来源白名单、跨租户查询/修改/删除拒绝、文件白名单与上传下载、Date/false 持久化、真实退出与重放拒绝；同一浏览器还通过真实 BFF 加载 11 个系统/视频/协同页面。设置 `ADMIN_TEST_FULL_DOMAIN=1` 后，配套协同三轮 216 项和摄像头接口 14 组也通过。脚本结束后停止并回收自己创建的临时集群，不访问现有 `.env` 或数据库。

初始入口约 2.84 MiB，异步拆分后约 1.65 MiB（未压缩，受构建工具舍入影响）；视频和页面组件按需加载，构建仍提示个别大包和浏览器兼容数据库过期。

## 依赖与验证边界

前后端生产依赖审计均为 0 漏洞。未使用 `npm audit fix --force` 降级 Parse Server。`@graphql-tools/utils` 更新到修复版本，并将其 promise helper 约束到兼容现有 Node.js 20 的 1.3.x；UUID 统一使用保留 CommonJS 接口的 11.1.1。已验证 Parse Server 模块加载、GraphQL Schema/查询、Google 依赖实际 UUID 调用和真实 PostgreSQL 持久化。

持久化与领域回归使用新建临时集群、随机账号和隔离存储，没有修改既有数据库、账号或生产配置；Schema 创建和迁移只发生于临时库。内存浏览器回归另外覆盖请求乱序及异常输入。真实 IPC 硬件、RTSP/HLS 解码和已部署 ONLYOFFICE 在线编辑未在本轮重新验收；协同按未配置 Office 的降级路径验证。结果覆盖已列明的缺陷和回归范围，不能证明任何系统绝对不存在其他缺陷。
