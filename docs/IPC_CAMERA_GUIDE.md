# 局域网 IPC 摄像头接入与回放

摄像头功能已升级为独立「摄像头管理」模块，含组织、设备、成员和视频中心。设备入口为 `/camera/devices`，旧 `/system/camera` 自动跳转。组织归属、成员授权和1–16分屏操作见 [摄像头独立模块指南](CAMERA_WORKSPACE_GUIDE.md)。系统通过 BFF 在局域网访问设备，浏览器只请求同源 `/api`，不使用厂商云账号、云视频或公网设备服务。

## 接入能力与品牌边界

| 设备 | 实时预览 | SD 卡 / NVR 历史录像 | 注意事项 |
| --- | --- | --- | --- |
| 海康威视 | ONVIF 获取通道或手填 RTSP | ONVIF Profile G，或海康 RTSP 时段回放 | 在设备内启用本地协议并创建有权限的 ONVIF/设备账号；NVR 按录像通道填写。 |
| 大华 | ONVIF / RTSP | Profile G，或大华 RTSP 时段回放 | 厂商回放需填写设备时区，UTC+8 为 480 分钟。 |
| 萤石 | 开放本地 RTSP / ONVIF 的型号 | 仅设备实际开放 Profile G 时 | 部分设备需要开启局域网预览，密码可能为设备验证码；具体以设备设置为准。云录像不支持。 |
| 小米 | 已开放 RTSP / ONVIF 的型号或固件 | 仅设备实际开放 Profile G 时 | 仅支持米家 App/云协议的设备无法直接纯本地接入；不提供绕过设备鉴权或未经授权的固件改装。 |
| 其他品牌 | 标准 ONVIF Profile S / RTSP | 标准 ONVIF Profile G | ONVIF Media1 HTTP 服务；仅 Media2、HTTPS 服务和私有 SDK 不在当前适配范围。 |

品牌路径是填写建议，不是兼容性证明。所有品牌只要能提供本地 RTSP，都可以由本服务器录制、回放；设备 SD 卡/NVR 历史回放另需录像服务能力。没有开放协议的设备不会因为扫描发现就自动获得视频接入能力。当前不包含 PTZ、对讲、音频、告警、设备固件升级、录像下载和云端接口。

## 服务器部署

1. 安装带 `libx264` 编码器的 FFmpeg，使用受维护的发行版，并确认运行 BFF 的账号可以执行它。
2. 在后端 `.env` 添加下表配置，生成并妥善备份独立的设备加密密钥。
3. 执行 `npm run migrate:camera`，创建 PostgreSQL `camera` 私有 Schema。该迁移只新增领域表，不更改现有 Parse 业务表。
4. 重启 BFF。管理员重新登录或刷新动态菜单时，系统会幂等补齐摄像头 Route。岗位管理也会补齐目录，可按页面授予查询、新增、编辑、删除权限。
5. 在页面手动关联或扫描，保存后通过实时预览验证设备接入。先用少量设备评估服务器 CPU、网络和磁盘，再增加录像通道。

```powershell
cd admin_server
# 将生成值写入本机 .env 的 CAMERA_ENCRYPTION_KEY，禁止提交到仓库。
node -e "process.stdout.write(require('crypto').randomBytes(32).toString('base64'))"
npm run migrate:camera
npm start
```

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `CAMERA_ENCRYPTION_KEY` | 空 | 32 字节随机密钥的 Base64。缺省时不能保存凭据或启动录像。变更密钥后需重新填写已有设备密码。 |
| `CAMERA_FFMPEG_PATH` | `ffmpeg` | FFmpeg 可执行文件路径；可以是绝对路径。 |
| `CAMERA_STORAGE_DIR` | `resources/cameras` | 后端私有录像与 HLS 临时目录，不能配置为前端静态发布目录。 |
| `CAMERA_ALLOWED_CIDRS` | 空 | 逗号分隔的私网 IPv4 CIDR；空时只允许 BFF 网卡直连网段。跨 VLAN 用明确网段放行。仍拒绝公网、回环、链路本地、DNS 主机名和 IPv6。 |
| `CAMERA_MAX_STREAMS` | `8` | 服务器录像 FFmpeg 任务上限，不是可关联设备总数。 |
| `CAMERA_MAX_LIVE_STREAMS` | `32` | 实时预览与设备回放的独立并发上限，允许16–128，视频中心支持1–16分屏。 |
| `CAMERA_MAX_STORAGE_MB` | `10240` | 服务器已完成录像和活动录像段预留空间的总配额，单位 MiB；超额删除最旧完整录像。 |
| `CAMERA_RETENTION_DAYS` | `7` | 完整服务器录像的保留天数；到期自动删除。 |

仅支持单个 BFF 录像实例：媒体任务与播放会话保存在内存。多实例部署必须按会话固定路由，并拆分录像任务所有权后再启用；当前不要在共享录像目录上运行多个 BFF 录像守护任务。设备返回的 ONVIF 端点和 RTSP 初始地址必须属于同一个已允许的私网 IP；FFmpeg 仅开启 RTSP/TCP/RTP 所需输入协议。建议把摄像头放在隔离网段，并限制 BFF 到摄像头网段的网络出口，以同时约束不可信设备的协议重定向。

## 关联设备与封面

1. 点击「扫描局域网」。服务从 BFF 网卡发送 TTL=1 的 WS-Discovery Probe，约 4 秒返回，最多 256 个发现结果；不会自动登录或保存设备。
2. 点击结果中的「关联设备」，或选择「手动关联」。填写名称、私网 IPv4、品牌、端口、RTSP 相对路径、本地账号密码、安装位置。地址范围由服务器配置决定，客户端不能传公司 ID 改变归属。
3. 保存后打开「配置 → 读取已保存设备的 ONVIF 通道」，选择通道并再次保存。若 ONVIF 不可用，直接填写设备文档提供的 RTSP 路径。每条 RTSP 通道作为一项设备配置，企业内相同 IP、端口、路径不能重复关联。
4. 编辑时密码不会回显；留空保留原密码。输入密码只通过保存请求传入 BFF，数据库使用 AES-256-GCM 加密。
5. 点击「封面」上传 512 KiB 以内 JPEG、PNG 或 WebP。服务端校验文件签名，封面不公开静态发布，每次访问重新验证权限与企业归属。

常见路径仅供参考：海康 `/Streaming/Channels/101`；大华 `/cam/realmonitor?channel=1&subtype=0`；部分萤石 `/h264/ch1/main/av_stream`。设备型号或固件不同可能需要其他路径。不要把账号密码写在路径中。

WS-Discovery 通常不能跨 VLAN，也无法发现关闭 ONVIF 或只支持厂商 App 的设备；扫描无结果不等于没有摄像头。Docker/虚拟机部署时，应确认 BFF 的网络能发送 UDP 多播并接收回复，Windows 防火墙允许 Node 对 UDP 3702 的发现通信。跨网段优先手动填写 IP。

## 实时预览

点击「实时预览」。BFF 使用 RTSP/TCP 拉流，再通过 FFmpeg 转成 H.264 HLS。支持 Chrome、Edge 的 MSE/HLS.js 与 Safari 原生 HLS，通常有数秒缓冲。H.265 输入由 FFmpeg 解码，输出宽度最多 1280 像素、20 fps；当前不保留音频。

清单和片段绑定创建用户与企业，其他账号即使拿到 URL 也不能播放。关闭窗口释放 FFmpeg 和临时文件。超过 90 秒没有媒体请求或最多 65 分钟的会话会回收，需要重新打开；退出或撤销页面权限后媒体请求同样失效。

## 服务器本地录像与回放

1. 在摄像头配置中开启「服务器持续录像」并保存。BFF 每 15 秒检查数据库，启动或恢复已启用的录像任务，前端页面关闭后仍录制。
2. 每段最长约 5 分钟、128 MiB，输出无音频 H.264 MP4。完整段原子改名后才进入列表，不完整段不可播放。
3. 打开「录像回放 → 服务器本地录像」，刷新列表、点击播放。浏览器支持原生进度拖动，Range 请求也会重新校验权限；最多展示最新 1000 段。
4. 配额不足或录像到期时自动删除最旧完整录像。磁盘可用空间不足时暂停新段，页面返回录像错误状态。需要长期保留的录像应由运维另行归档。

这是一套有界的本地录像能力，不是保证连续无损的专业 NVR。设备断线、CPU 满载、任务并发上限和分段重启可能造成缺口；修改连接配置、关闭录像或 BFF 退出会丢弃当前未完成段。关联设备最多每企业 500 个，实际并发取决于服务器资源。

## 摄像头 SD 卡 / NVR 历史录像

1. 打开「录像回放 → 设备 SD 卡 / NVR 历史录像 → 读取设备录像服务」。
2. 支持 Profile G 时显示设备返回的录像 token，选择录像源和过去的一段时间，单次最长一小时，点击播放。服务请求 `GetReplayUri`，通过本地 RTSP 桥在 PLAY 请求中注入绝对 UTC `Range: clock` 和 `Require: onvif-replay`，同时重算 Digest。
3. 海康、大华还可选择「厂商 RTSP 回放」，填写设备录像通道及时间段。大华还需填设备实际 UTC 偏移（分钟）；中国标准时间为 `480`。厂商路径不保证所有 OEM/固件一致。
4. 只有对应时段真实存在录像且设备账号有回放权限时才能播放。Profile G 录像 token 只是录像配置，不保证所选时段有视频；当前没有设备录像日历/精确事件检索。通过重新选择区间定位历史录像。

设备回放 HLS 缓存会临时占用额外磁盘空间，最多保留单次一小时的转码结果，关闭播放器后删除；此部分不属于服务器已完成录像配额，应留足磁盘余量。

## 验证与排错

```powershell
cd admin_server
npm run check
npm run security:check
npm run test:camera
# 可选：指定本机 MediaMTX 可执行文件，验证真实 RTSP → HLS 和录像产出。
$env:CAMERA_TEST_MEDIAMTX="C:/tools/mediamtx.exe"
npm run test:camera
# 先在 vue_admin 执行 npm run build，浏览器回归将同源启动生产构建和隔离 BFF。
$env:CAMERA_TEST_BROWSER="1"
npm run test:camera
```

回归脚本使用两个随机隔离企业、临时成员与临时磁盘目录，完成后删除自己创建的数据，不扫描真实局域网设备。MediaMTX 仅作为测试视频源，产品运行无需安装它。浏览器测试截图只包含模拟摄像头信息。

| 提示 | 检查项 |
| --- | --- |
| 数据库不可用/未迁移 | PostgreSQL 连接、`camera` Schema 权限、`npm run migrate:camera`。 |
| 密钥无法解密 | 恢复原 `CAMERA_ENCRYPTION_KEY`，或重新输入该设备密码。 |
| 不在允许网段 | BFF 实际运行网卡、`CAMERA_ALLOWED_CIDRS`、跨 VLAN 路由。 |
| ONVIF 认证/服务失败 | HTTP 服务端口、ONVIF 开关、独立 ONVIF 账号权限、设备与服务器时间一致。 |
| 无可播放画面 | FFmpeg 包含 libx264、RTSP TCP 端口、设备密码/验证码、路径、主子码流、设备连接数限制。 |
| 设备历史回放失败 | Profile G 或厂商本地回放支持、实际录像时段、通道号、SD 卡状态、回放权限和时区。 |
| 并发上限 | 关闭其他预览，减少同时录像设备，评估资源后调整上限。 |

本次软件回归使用模拟设备，不能替代真实萤石、大华、海康、小米型号与固件验收。上线前应逐型号确认开启本地协议、预览、服务器录像、设备历史回放和断线恢复。
